# Security Policy

Thank you for helping keep OpenBrau and its users safe.

## Reporting a Vulnerability

Please **do not** open public issues for suspected security vulnerabilities.

Instead, report security concerns privately to the project maintainers through the project's designated private contact channel. If a dedicated security email address is added later, this file should be updated to include it.

When reporting a vulnerability, please include:

- a clear description of the issue,
- affected components or files,
- reproduction steps or proof of concept if available,
- the potential impact, and
- any suggested mitigations.

## What to Expect

Maintainers should aim to:

- acknowledge receipt of the report,
- investigate the issue,
- validate impact,
- prepare a fix, and
- coordinate disclosure responsibly.

Response times may vary depending on maintainer availability and report severity.

## Scope Guidance

Security-sensitive areas may include, but are not limited to:

- authentication and session handling,
- database access and migrations,
- file import/export flows such as BeerXML,
- webhook or telemetry endpoints,
- deployment and container configuration, and
- secrets or environment variable handling.

## Responsible Disclosure

Please give maintainers a reasonable opportunity to investigate and remediate the issue before public disclosure.

A calm private report is always more helpful than a surprise boil-over on the public issue tracker.
